# 嘉实财富 · 投研工作台 UI 优化方案

日期：2026-09-11  
范围：当前 React 前端的视觉体系、信息架构与主要投研路径。本文是可实施的设计提案，未修改业务代码。

## 1. 设计判断

建议将界面重心调整为**研究结论、依据与适用条件**，建立机构投研的严谨感和财富服务的克制感。用户应先看清研究对象、分析时点、关键判断和风险，再按需要进入证据、分歧与研究过程。

当前界面已经有行情、报告、交易建议、风险列表和多智能体工作流，问题主要在于视觉语言分散，以及结果被过程挤到页面下方。替换蓝紫渐变、收紧卡片圆角，只能解决其中一部分；更高优先级的是改变首屏信息顺序，明确金融数据与模型结论的边界。

建议保留“嘉实财富”品牌名，将产品名称统一为“投研工作台”。技术架构、Agent 数量、模型配置、Git commit 等信息放在研究过程或系统设置中。研究过程中仍然可以清楚看到多 Agent 的参与，但无需把全部节点常驻在主工作区。

工作区诊断基于当前 React 源码；本地登录页已实看，登录后的业务页面没有逐页操作。实际入口是 `frontend/index.html → src/main.tsx → index.css`，旧版 `styles.css / main.js` 不作为当前样式依据。推广横幅的配置目前为 `enabled: false`，也不计作当前界面问题。配套概念预览采用明确标注的示意数据，展示今日关注、标的研究、证据与分歧、完整报告及研究过程。

## 4. 视觉体系

### 4.1 色彩与表面

以下均为本方案提议值，**不代表嘉实财富官方 VI**。正式实施时，应核对品牌授权资产和规范；本地 `frontend/public` 尚未发现正式嘉实品牌 Logo。

| Token | 提议色值 | 用途 |
| --- | --- | --- |
| `brand-primary` | `#172D40` | 桌面导航、主要操作、重要标题 |
| `canvas` | `#F4F6F8` | 工作区背景 |
| `surface` | `#FFFFFF` | 图表、文档、表格主体 |
| `text-primary` | `#243746` | 正文与关键数据 |
| `text-secondary` | `#657582` | 标签、说明、次级信息 |
| `border` | `#DFE5E9` | 容器边界、分隔线 |
| `brand-detail` | `#92764E` | 少量品牌细线、编号、文档封头细节 |
| `market-up` | `#AF423F` | A 股上涨、看多等同方向语义 |
| `market-down` | `#287461` | A 股下跌、看空等同方向语义 |

页面大面积使用冷白与纸白。墨蓝建立导航和操作焦点；铜色只用于非常有限的品牌细节，不用于长段文字、不作为第二种主按钮颜色，也不用来包装风险标签。

风险状态使用独立的状态体系：名称、图标、边框和文本共同表达“待评估 / 已通过 / 需修订 / 不通过 / 无法确认”。即便颜色接近涨跌色，也必须有完整文字；不能让“绿色”同时暗示下跌、低风险和可执行，而缺少语义标记。

### 4.2 字体、字号与数字

- 中文 UI 使用 `PingFang SC / Source Han Sans SC / Microsoft YaHei / sans-serif`；英文与数字使用 `IBM Plex Sans`，中文回退到前述字体。字体未加载时保持布局稳定。
- 所有可比较数值开启 `font-variant-numeric: tabular-nums`。表格数值右对齐，代码与名称左对齐；普通金融数值不需要整页使用等宽代码字体。
- 宋体仅用于完整研报的标题、章节题名等少量位置。导航、按钮、表格与高密度数据仍用黑体。
- 页面标题建议 24–28px / 600；区块标题 16–18px / 600；常规正文与表格 14px；辅助信息 12–13px；长报告正文 15px、行高 1.7。
- 价格主数字可用 28–32px。不要把系统状态、Agent 数量或置信度做成同等级的大数字。

### 4.3 容器与控件

- 8px 基础间距；主区块内边距 20–24px，紧凑表格行高 44–48px。
- 主容器 8px 圆角；按钮、输入框和小型控件 4px。状态标签优先小矩形，避免大面积胶囊。
- 1px 实线边框；页面上的常驻容器无明显投影。菜单、弹层和抽屉使用轻阴影。
- 一个工作区保留一个明确主操作；次级操作用描边或文字按钮。危险操作用专属颜色并与主操作保持距离。
- 图标统一 16–18px、统一线宽；删除机器人、魔法星光等无业务含义的主视觉元素。业务图标可以保留，但不需要每个标题配一个彩色底座。

### 4.4 动效

- hover/focus 仅改变背景、边框或文字色，时长 120–160ms；不让卡片上浮、放大或发光。
- 抽屉展开、标签内容切换使用 160–200ms 的轻微过渡；不使用大幅位移、弹簧反弹或彩色扫光。
- 加载时允许一个旋转图标或细进度条；避免同屏同时出现多个转圈、跳点和呼吸灯。
- 行情更新不让数字宽度跳动；如需提示变化，使用一次性、短时淡背景，不常驻闪烁。
- 尊重 `prefers-reduced-motion`：关闭位移动画和闪动，只保留必要的状态文本变化。

### 4.5 明暗色

优先验证浅色主题，它更适合长时间阅读报表和研究文本。保留“浅色 / 深色 / 跟随系统”选择，三者共享信息层级与金融语义。

深色主题采用不发光的深墨蓝/炭灰表面，而不是渐变背景。可从背景 `#111B24`、容器 `#172530`、正文 `#E8EDF1`、辅助文字 `#A4B2BE`、边框 `#31424F` 起步；涨跌色使用同色相、满足深色背景对比度的亮度变体。最终颜色通过实际对比度检查确定，不能机械反转浅色。

普通文本对比度至少 4.5:1，大号文本和关键非文本界面至少 3:1。涨跌、风险和选中状态同时提供文字、符号或轮廓，不依赖颜色单独表达。

## 5. 页面结构与线框

### 5.1 全局框架

桌面导航固定 184–208px，默认展示文字。顶部栏保持 56–64px，提供当前工作区、全局搜索/标的搜索、通知和账户入口。系统信息、主题切换、设置进入账户菜单；GitHub、致谢等入口进入“关于”，不占据研究操作区。

建议导航顺序：今日工作 / 标的研究 / 研究报告 / 自选与跟踪 / 设置。若暂时不能合并当前自选与跟踪功能，保留独立路由，但明确区分“关注标的与定时研究”和“持仓跟踪”，避免标签重叠。

### 5.2 今日工作

首页回答三个问题：今天应关注哪些标的、哪些研究刚更新、哪些事项仍需要处理。

```text

│ 嘉实财富 · 投研工作台                     标的搜索      通知   账户   │
├───────────────┬──────────────────────────────────────────────────────┤
│ 今日工作      │ 今日工作                 交易日 / 数据时间   新建研究 │
│ 标的研究      │ 跟踪标的数 · 最新研究数 · 当前任务状态                │
│ 研究报告      ├────────────────────────────────┬─────────────────────┤
│ 自选与跟踪    │ 今日关注                       │ 最近研究            │
│               │ 标的 / 最新价 / 涨跌 / 研究更新 │ 标的 / 结论 / 时间   │
│               │                                │                     │
│               │ 行可进入标的研究或跟踪详情     │ 进行中的研究        │
│               │                                │ 阶段 / 已用时间      │
```

第一阶段只使用真实已有字段：最近研究、报告时间、跟踪数量、行情覆盖和实际任务状态。如 Dashboard API 仅返回跟踪元数据，就先展示紧凑摘要与完整看板入口；需要明细时改为经过授权的现有接口或新增正式接口。不得凭前端生成“今日机会数”“高风险数量”“超额收益”等不存在的数据。

### 5.3 标的研究：完成态

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 标的名称 / 代码 / 市场        研究周期     数据截至时间    重新研究   │
│ 最新价 / 涨跌幅 / 货币单位    研究生成时间               研究助理   │
├──────────────────────────────────────────────────────────────────────┤
│ 研究判断                   当前动作                   风控状态       │
├──────────────────────────────────────────────────────────────────────┤
│ 研究概览    行情与指标    证据与分歧    完整报告    研究过程          │
├───────────────────────────────────────┬──────────────────────────────┤
│ 行情主图                              │ 关键研判                     │
│ 区间与周期控件                        │ 支持依据 / 关键反证          │
│                                       │ 核心理由 1、2、3             │
│                                       │ 适用条件与关键风险           │
├───────────────────────────────────────┴──────────────────────────────┤
│ 关键指标表：估值、成交、趋势等已有字段，显示单位与时点                 │
│ 主要依据 / 待关注事项 / 查看完整报告                                   │
└──────────────────────────────────────────────────────────────────────┘
```

标的头下常驻一条摘要带，分开呈现研究判断、当前动作和风控状态。概览中的主图与关键研判建议约 60/40 分栏，主图约 300–360px 高；概念预览为适应会话展示宽度采用更紧凑尺寸。不要把全部报告、Agent 图、指标列表和聊天记录同时排在概览首屏。

关键研判默认展示：方向判断、建议动作、适用周期、核心依据和未解决风险。方向、动作、风控状态分开，允许表达“方向偏多 / 建议观望 / 风控需修订”等合法组合。尚未接入风控字段时显示“风控状态未提供”，不依据买入信号推断“已通过”。

现有自由文本不能可靠提取出结构化理由、条件时，优先展示已有完整摘要或可展开原文，并标识来源章节；不要截取前 300 字就当成完整推理。后端提供结构化摘要后再升级卡片。

### 5.4 标的研究：进行态

将常驻 810px 工作流替换为一条阶段提示：数据准备 / 分项研究 / 多空论证 / 风险复核 / 形成结论。显示当前阶段、已用时间、最后更新时间和查看详情入口。

阶段只能由真实任务事件推导。不支持可靠进度百分比时，用阶段与完成项数，不制造精确剩余时间。断线恢复、执行失败、等待重试是独立状态，不能继续显示“正在研判”掩盖错误。

已生成章节可以提前阅读，但未完成的结论明确标记“生成中”。如保留旧报告，在标题处显示“上一版研究”与其生成时间，新任务状态另外呈现，防止用户误认为旧结论是本次结果。

### 5.5 研究助理

- 页面主标题旁放“研究助理”按钮，默认不抢占研究阅读空间；桌面打开后位于右侧，宽 300–320px。
- 助理上下文显示当前标的、周期和数据时点。切换标的或报告时同步上下文，避免跨标的引用。
- 快捷输入用实际业务动作，如“解释主要分歧”“哪些条件会改变结论”“查看关键风险依据”；普通首次提问仍可自然输入。
- 流式 Agent 内部过程不重复写满聊天记录；默认只显示必要进度、回答和可跳转章节。
- 清空聊天、重新发起研究、删除报告等动作明确区分。聊天清空不应在文案上暗示只是清空消息、实际却连同研究结果一起删除。

### 5.6 证据与分歧

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 证据与分歧    关键问题优先    全部 / 待核验 / 有分歧                  │
├──────────────────────────────────────────────────────────────────────┤
│ 争议问题 / 对结论的影响                                              │
│ 支持依据：来源、发布日期、可得时间、摘录                              │
│ 反对依据：来源、发布日期、可得时间、摘录                              │
│ 裁决理由 / 尚缺信息 / 核验状态                                       │
├──────────────────────────────────────────────────────────────────────┤
│ 下一项争议                                                         │
└──────────────────────────────────────────────────────────────────────┘
```

这部分可充分体现多 Agent 价值，但必须建立在真实数据结构上。现有“resolved”若只是某个 Agent 自报，只能显示“已回应”，不能设计成“证据核验通过”。没有可追溯出处时显示“来源未提供”；核验失败、无法确认和仍有争议分别表达，不强制形成绿色完成状态。

### 5.7 完整报告与研究过程

完整报告采用窄目录 + 正文。默认定位研究结论，后续依次阅读核心依据、关键风险、分歧、分项研究、方法说明。正文宽 680–800px；超宽表格在容器内滚动，不能让整个页面横向溢出。

报告页首显示标的、周期、生成时间、数据截止时间、报告版本和导出入口。引用跟随具体陈述，笼统的“交易所 / 财报 / 多智能体生成”仅能作为方法说明，不能替代来源。

研究过程默认采用阶段列表，展开可查看 Agent 产出、时间和状态。现有 React Flow 图保留为高级视图，适合理解架构和诊断流程，不再成为查看报告的唯一入口。

## 6. 数据表达与状态规范

### 6.1 金融数字

- A 股默认红涨绿跌，涨跌幅同时提供 `+ / −` 符号。若未来支持其他市场，按产品统一设置表达，并在设置中明确说明，不在单个组件自行反转。
- 价格、涨跌额、涨跌幅分列；人民币资产标记 `CNY / ¥`，其他币种不沿用人民币符号。
- 金额和成交量按业务字段统一单位，例如元/万元/亿元、股/手；单位放在列头或紧邻数值，禁止只为缩短字符而静默换算。
- 相同列保留相同小数位；比较价格通常两位小数，但基金净值、指数、汇率等按实际精度确定。不能一律四舍五入到两位。
- `0` 是真实零值；缺失用 `—` 并解释缺失原因，加载用骨架或“读取中”，不共用一个符号混淆状态。
- 目标价、止损价需要分析时点、期限及来源；不把目标价固定染红、止损价固定染绿来暗示收益保证。
- 同屏展示行情截至时间与报告生成时间；二者不同不能合并为模糊的“刚刚更新”。

### 6.2 状态矩阵

| 状态 | 界面行为 | 避免的问题 |
| --- | --- | --- |
| 首次空态 | 显示简洁说明、标的输入和单一“新建研究”操作 | 不用大幅机器人插画，也不填充假数据 |
| 有数据但无研究 | 保留行情与标的信息，说明暂无研究结论 | 不将空报告等同于分析失败 |
| 正在加载 | 固定容器尺寸，局部骨架或一次加载提示 | 不让整页跳动或每格同时闪烁 |
| 数据部分缺失 | 只标记缺失列/区块，显示可用内容与缺失说明 | 不让某个接口失败清空整个工作台 |
| 分析执行失败 | 展示失败阶段、可理解原因和重试入口 | 不继续显示“研判中” |
| 网络中断后恢复 | 明确显示重连/已恢复，并保持已有结果 | 不重复插入相同分析消息或覆盖时间信息 |
| 过期/滞后 | 标注数据日期或距更新时间；按数据类型判断 | 不把休市日没有变化一律当成故障 |
| 风控缺失 | 显示“风控状态未提供”，保留研究方向 | 不推断已通过，不把未评估显示成低风险 |
| 无证据来源 | 显示“来源未提供”，允许查看原始章节 | 不使用“已核验”或权威机构徽章包装 |
| 无权限 | 解释当前不可访问的对象与返回入口 | 不暴露敏感数据，不把权限错误写成暂无记录 |

过期阈值应根据行情、财报、新闻和报告各自的更新时间及交易日历确定，需要真实服务端时间与字段支持。前端不采用统一的“超过 N 分钟就过期”规则覆盖所有数据。

## 7. 响应式与可访问性

- ≥1440px：184–208px 文字导航；研究概览左右分栏；研究助理可侧开，但主报告保留足够阅读宽度。
- 1024–1439px：导航允许用户手动折叠；助理优先使用覆盖式抽屉；图表和摘要按可用宽度决定左右或上下排列。
- 768–1023px：折叠导航；标的头分两行；摘要位于图表上方；标签栏允许横向滚动且保留清晰选中状态。
- <768px：单栏；助理全宽抽屉；重要按钮触控目标至少 44px；表格只在局部容器横滚。
- 不通过缩小到 10px 字号来塞进完整工作流。小屏主要路径仍为标的→结论→风险→依据。
- 全部交互支持键盘、可见 focus ring 和有意义的 aria 标签。抽屉打开后管理焦点，关闭后返回触发按钮；表格列头采用语义标签。

## 9. 实施分期

### 第一阶段：统一视觉与标的首屏，P0

目标是让同样的数据更容易阅读和判断。先落地 tokens、品牌名称、导航稳定性、浅色主题、数值样式；再重排 Analysis，让结论和风险进入首屏，将 Agent 图移入研究过程。Dashboard 收紧系统统计，优先显示真实最近研究与跟踪摘要。

该阶段可以主要复用已有字段，不改变分析引擎。针对没有结构化来源、风控状态或条件的内容，保留明确缺失态。先以一个真实结构、脱敏内容的完成报告和一个进行中任务作为样板验证。

### 第二阶段：报告、助理与连续工作路径，P1

落地报告默认章节、目录、标签切换、右侧助理、响应式及完整的空/错/加载状态。打通首页→研究→依据→报告→追问的路径；保留流式输出、中断恢复、导出和历史查看能力。丰富跟踪列表前，确认接口权限与已有字段。

### 第三阶段：证据核验与风控可信展示，P1/P2

与后端改进一起推进证据来源、可得时间、争议状态、风控硬约束和报告版本。将“已回应”与“已核验”分开，将“研究方向”与“执行许可”分开。后端尚未提供可核对结果时，前端不得点亮“已核验”“已通过”“可执行”。

本阶段不是用 UI 掩盖模型或数据不确定性，而是让不确定性与业务约束被准确看见。置信度只有在定义、样本外校准和展示口径明确后，才考虑升级为更显著的量化指标。

## 10. 验收标准

### 信息与任务

1. 在 1440×900 的完成报告页面，首次进入且未滚动时，可看到标的、周期、行情/报告时点、研究方向、建议动作、主要风险和至少一条核心依据。
2. 从研究概览到完整结论、某条风险依据或研究过程均不超过一次点击；不要求先点击 Agent 节点。
3. 未完成研究、旧报告、数据缺失和风控未提供状态可以明确区分；无伪造行情、核验、在线状态或通过状态。
4. 完整报告默认呈现研究结论；切换报告后目录和内容同步，不能保留上一个标的的助理上下文。

### 视觉与可访问性

5. 主工作区没有常驻渐变背景、光晕、卡片上浮和多处跳点；圆角遵循 8px 容器 / 4px 控件，浮层之外不使用明显阴影。
6. 同一市场的上涨、下跌、多空及数值变化采用一致映射；所有关键状态都能在灰度或色觉差异情况下通过文字辨认。
7. 浅色和深色主题均达到文字与关键控件对比度要求；普通表格文字不小于 12px，核心数据与正文不小于 14px。
8. 在 1440、1280、1024、768、390px 宽度下检查：页面无全局横向溢出，关键文本不被固定容器裁切，局部宽表可滚动。
9. 键盘可以完成导航、标签切换、助理打开/关闭、报告导出；焦点可见且不会留在关闭的抽屉中。

### 数据与回归

10. 真实零值、缺失、读取中、执行失败、过期数据分别展示；所有金融数字有一致单位与精度，时间明确区分数据时点和生成时点。
11. SSE 输出、分析恢复、标的切换、历史报告、导出、主题持久化及现有鉴权流程通过与改动相关的回归检查。
12. 对一个完成报告、一个进行中任务、一个失败任务、一个空账户和一个部分缺失案例做截图复核；不只验收“最好看”的完成态。

建议使用相同任务进行改版前后可用性比较：请实际目标用户找出“当前建议、最重要的风险、数据截止时间、改变结论的条件”。记录完成时间、误读率和首次点击路径。以任务结果评估专业感是否落到了使用体验上，而不只看配色偏好。
